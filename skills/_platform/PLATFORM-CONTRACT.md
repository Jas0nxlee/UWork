# 工作项模板契约 v1（部门自定义前必读）

这份文件告诉你：**哪些能改、哪些不能改、改错了会怎样**。它是平台生成的单一来源，
随模板包一起分发；部门模板的 `SKILL.md` 只引用它，**不要复制**（复制就会各说一套）。

对应的机器可读版本是 `work-item-contract.v1.json`；校验器是 `work-item-contract.mjs`
（部门本地、agent 填卡前、服务端入库前，**同一个实现**）。

## 一、不能改（只读）

| 项                 | 说明                                                                                                                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **骨架字段**       | 提交人 / 所属部门 / 项目编号 / 项目名称 / 工程师 / 项目经理 / 开始日期 / 结束日期 / 周期 / 标题 / 简述 / 详细内容 / 遇到的问题 / 工作输出物（附件）/ 分类标签 / 创建人 / 创建时间 / 最后编辑人 / 最后编辑时间。**可以引用，不能重命名、删除、改类型。** |
| **周期格式**       | `YYYY-MM`（如 `2026-10`）或 ISO 周 `YYYY-Www`（如 `2026-W43`）。                                                                                                                                                                                        |
| **消息与卡片协议** | 卡片是数据（`title/sections/attachments/actions` + 必填 `fallback`），渲染原语不可扩展。                                                                                                                                                                |
| **校验器集合**     | 只有下面列出的几种。**不允许自带脚本、表达式或任意代码。**                                                                                                                                                                                              |

## 二、可以改（部门自服务）

1. **追加字段**：在 `fields` 里加你们要的列（例：`测试方式`、`测试内容分类`、`被测对象版本`）；
2. **追加词表取值**：`vocabulary.json` 里加受控取值（例：`"14-系统联试/联调"`）；
3. **在有意义的范围内设必填与默认值**（骨架字段的必填是平台定的，不要在 `fields` 里重复要求）；
4. **导出列顺序与表头**：`export.columns.json`（你们现在那张 xlsx 的表头就写在这）；
5. **提示词与归纳规则**：`SKILL.md` 里怎么写、怎么问、什么时候必须追问。

## 三、硬上限（防止把台账用坏）

| 限制            | 值          |
| --------------- | ----------- |
| `fields` 字段数 | ≤ 40        |
| 字段标签长度    | ≤ 40 字符   |
| 单个字段文本    | ≤ 2000 字符 |
| `tags` 项数     | ≤ 20        |
| 单个词表取值数  | ≤ 200       |
| 模板包体积      | ≤ 1 MB      |

## 四、允许的校验器

| 校验器       | 含义                     | 例                                  |
| ------------ | ------------------------ | ----------------------------------- |
| `required`   | 必填                     | `{"required": true}`                |
| `oneOf`      | 取值必须来自词表         | `{"oneOf": "测试内容分类"}`         |
| `range`      | 数值/日期范围            | `{"range": {"min": 0, "max": 100}}` |
| `length`     | 长度上限                 | `{"length": {"max": 500}}`          |
| `pattern`    | 受限正则（不含回溯写法） | `{"pattern": "^[A-Z]{2}-\\d{4}$"}`  |
| `dateFormat` | 日期格式                 | `{"dateFormat": "YYYY-MM-DD"}`      |

**不允许**：`script`、`expression`、`custom`——那等于让模板往服务端注入代码。

## 五、两条纪律

1. **改了就发新版本号**（`templateVersion` 递增）。已发布的版本不要改：旧记录永远按它当时的定义解释，
   否则你们改一次字段，历史导出就会跟着变形。
2. **词表里用过的取值不要删**：要弃用就标 `deprecated`。删掉会让历史记录出现"取值不在词表里"，
   导出与校验互相打架。

## 六、怎么自查

```bash
# 校验模板本身（发布前跑）
node skills/_platform/work-item-contract.mjs --template skills/dept-qa-report

# 校验一份要提交的内容（agent 填完卡、提交前跑）
node skills/_platform/work-item-contract.mjs --template skills/dept-qa-report --payload /tmp/draft.json
```

两处都通过，再提交；服务端会用**同一个实现**再校验一次（那是事实边界）。
