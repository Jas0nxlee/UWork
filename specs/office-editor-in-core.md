# 内核 DOCX 编辑器（在 UWork 里直接编辑 Word 文件）

状态：已实现（分支 `chore/upstream-v3.15.1-sync`）。组件落点 `packages/ui/src/officeEditor/`。
引擎与选型调研见同类文档 `office-in-core-research.md`（在插件仓 `UWork-plugin/specs/`）。

## 1 目标与非目标

**目标**：在 UWork 侧栏里直接编辑 `.docx`，操作与观感对标 Word/WPS（功能区 + 纸张居中 + 分页），
显式保存写回原文件并留备份。

**非目标（本期明确不做）**：

- 不做 Word 修订记录（`w:ins`/`w:del`）：canvas-editor 无修订语义，这是调研里的 C2；
- 不拉起本机 Office、不引入 ONLYOFFICE/Collabora 这类服务端重型方案（用户的硬约束）；
- 不动预览面板（保持只读，上游契约），编辑器是独立的一屏。

## 2 引擎选择（决策）

**canvas-editor**（MIT）：壳 808 KB + docx 插件 711 KB，canvas 渲染、自带分页/光标/选区/表格/图片工具栏。
否掉的：SuperDoc（自包含不可行：引擎 12.7 MB 从 jsdelivr 拉、worker 用相对路径、引擎本身是独立商业包）、
ONLYOFFICE/Collabora（服务端重型）。许可按仓库口径核查（`scripts/licenses.mjs`，AGPL 为红）。

## 3 数据与接口

| 环节 | 契约                                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------------------- |
| 读   | `IFileService.readBinaryPreview({ path })`（base64 + totalBytes）+ `stat`（size/mtimeMs 作为 baseRevision） |
| 写   | `IFileService.writeBinaryFile({ path, dataBase64, expectedRevision?, backup: "sibling" })`                  |
| 冲突 | 写前比对 size/mtime，不一致则拒绝（`File revision mismatch`），界面提示"重新加载或另存副本"                 |
| 备份 | 写前复制为 `<stem>_backup.docx`，已存在则 `_backup-2`、`_backup-3`…（唯一持久回退手段）                     |
| 落盘 | 先写 `<path>.<base36>.tmp` 再 `rename`（原子替换）                                                          |
| 上限 | 8 MiB 内原地编辑；超过则只提示只读（超大文档在任何浏览器编辑器里都不可用）                                  |
| 慢   | 解析超过 3s 时如实提示"会很卡"（实测：500 段 76ms / 6000 段 957ms / 20000 段 4.4s）                         |

命令映射在 `CanvasOfficeEditorPane.runRibbon`：功能区语义命令 → 引擎命令，参数形态**照抄 canvas-editor 官方 demo**
（特殊形态：`executePainter` 要 `{isDblclick}`、`executeInsertElementList` 的日期/复选框元素形状、
`executeImage/Hyperlink/Latex/AddWatermark` 收对象、撤销/重做前先 `focus()`）。

## 3.5 修订模式（C2）：改动落成 w:ins/w:del（2026-10-16）

顶栏「修订模式」开关**默认开**：保存时把本次改动与**打开时的文件**做对比，写成 Word 修订，
于是改动能进审阅队列（对话卡片逐条接受/拒绝读的就是这套标记）。

- 规则用插件仓已验证的那条——**公共前后缀 + 最小改动段**（`plugins/office-editor/server/docx_revisions.py`
  在那份 6000 修订的压测文档上对齐 5990/5990），这里做段落级移植（`docxTrackChanges.ts`）：
  相似（公共前后缀占比 ≥ 30%）判为"改写"（旧文 `w:del` + 新文 `w:ins`），不相似判为"删一段 + 加一段"；
  整段删除会把**段落标记**一起标成删除（`w:pPr/w:rPr/w:del`），Word 接受后该段才真的消失；
- 判据（回归检查逐条断言）：**接受全部修订 == 编辑后的样子**、**拒绝全部修订 == 基线**；
- 保存后基线更新为刚写回的内容（否则第二次保存会把上一次的改动再标一遍）；
- 明确不做：段内词级 LCS（整段包一层更保守）、表格结构变化、批注/脚注部件的修订。

## 4 界面规则（功能区）

宽度是**量出来的**，不设宽度阈值：侧栏可拖（窄约 650px、宽 1000px+），开始标签完整铺开要 1656px，
任何固定阈值都会导致"内容比容器宽"的横向滚动条，所以按 Word/WPS 的做法逐级降级：

1. 分组一行铺开；
2. 放不下的分组收进末尾的「»」菜单（点开仍是完整的一组命令）；
3. 单个分组自己都放不下时收成「分组名 ▾」按钮。
   取舍顺序由数据里的 `essential` 决定：必要分组优先，其余按原顺序；**任何宽度下都不出现横向滚动条**。
4. 分组行高度固定下限 **88px**（开始标签的样式库卡片最高，实测 85px）：切换标签时整块不跳动。

其它定死的规则（都对应真机反馈）：

- **下拉面板 portal 到 body + fixed 定位**：功能区有 `overflow-x-auto`，普通绝对定位会被裁掉（"字体下拉被困在栏里"）；
- **面板从触发器继承前景色/背景色**：portal 脱离主题作用域后 token 失效（"下拉文字颜色不对"）；
- **同屏只允许一个下拉打开**（单一打开源）：点第二个时第一个自动关闭，不依赖点击传播的细节；
- **字体给跨平台字体栈**（`宋体 → SimSun, Songti SC, STSong, serif`）：只写 Windows 字体名在 macOS 上解析失败，
  表现为"换了字体没变化"；
- **底纹只用浅色**：深色底纹会吞掉黑字，看起来像文字消失；
- **选区色 `#0969da` / 25%**：默认色在深色应用里与正文对比太弱，像"字没了"。

## 4.5 引擎没提供的能力（我们补的）

实测发现下面这些**不能靠命令名想当然**（无头探针逐条确认，见 `engineCommands.ts` / `officeEditorCommands.ts` 的注释）：

| 功能        | 引擎的真实情况                                                                                                  | 我们的做法                                                                              |
| ----------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 纸张大小    | `paperSize(width, height)` 收**像素**；传 `"A4"` 会把页面尺寸写成 NaN → 整页空白（真机反馈"切完纸张变白"）      | 预设 A4 794×1123 / A3 1125×1593 / A5 565×796 / B5 665×945（引擎内置映射就用这三组像素） |
| 插入控件    | 只给 `control.type` 会插出一个**空壳**，六种控件长得一模一样（真机反馈"每一个都一样"）                          | 按类型给整套配置：列举/复选/单选带 `valueSets`，日期带 `dateFormat`，各自有占位文字     |
| 复选框/日期 | 元素版是"一个方框"，未选时看着是空白（真机反馈"没法用"）                                                        | 改成**内容控件**：复选框控件（可勾选）、日期控件（点开是日期选择器、有占位文字）        |
| 分页/连页   | 引擎枚举是 `paging` / `continuity`；按字面写成 `"continuous"` 去比对，切过去就回不来（真机反馈"不能用"）        | 读 `getOptions().pageMode` 再翻转，并在功能区显示当前状态                               |
| 字数统计    | `executeWordTool` **不是**字数统计，它是"清理零宽空格"（真机反馈"点了没反应"）                                  | `getWordCount()`（worker 异步）+ 自己数"字符（不含空白）/段落"，结果进状态栏            |
| 查找替换    | `executeSearch` 只高亮、不移动选区；`executeReplace` 实测**无效**（默认 trace 开着时不走替换分支）              | `getKeywordRangeList` 取命中范围 + 自己设选区 + 插入替换文本；"第 n / 共 m"由我们维护   |
| 公式        | 引擎没有 `executeLatex`；但插入 `{type:"latex", value:"E=mc^2"}` 时引擎会**自己**转 SVG（`convertLaTextToSVG`） | 直接插 latex 元素，源码即可（不要自己传 SVG，会被覆盖）                                 |
| 缩放显示    | 缩放值不在任何事件里自动回填                                                                                    | 每条命令后读一次 `getOptions()`（纸张/缩放/模式/痕迹），缩放做成显示当前比例的下拉      |

**构造函数的坑（实测，影响最大）**：引擎是 `new Editor(容器, 数据, 选项)` **三个参数**。此前把选项当第二个参数（数据）传——引擎按 `IEditorData` 读它（恰好带 `main`，所以文档照常显示），于是 `margins`、选区色、控件定界符这些**选项从未生效**；真机上"选区色没变化""控件带花括号"都是这个原因。现在初始数据与选项分开导出（`createInitialData` / `createEditorOptions`），编辑位与回归检查共用同一份，检查里也会断言选项真的进了引擎。

**命中范围的坑（实测）**：`getKeywordRangeList` 返回的范围**不能直接用于选区**——选区是左闭右开，而它把起点多算了 1（"压测"两字返回 `{11,12}`，直接用只选中"测"；"段"一个字返回 `{5,5}`，直接用是空选区）。两种长度都只差"起点减 1"。

## 5 验收与回归检查

两条检查都在无头 Chromium 里跑（需要 `OFFICE_CHECK_CHROMIUM` 指到 `chrome-headless-shell`，
本机在 `~/Library/Caches/ms-playwright/chromium_headless_shell-1208/`）：

- `pnpm --filter @zcode/ui check:office-editor`（`scripts/check-office-editor-commands.mjs`）：
  在真实引擎里逐条跑功能区命令，断言 ① 不抛错 ② 不吞内容 ③ 取值类命令的元素属性真的被设置（标题级别、字号、字色、
  底纹、字体）④ 渲染哨兵用**截图字节数**（GPU 画布在无头环境 `getImageData` 取不到数据，会假通过）。
  命令矩阵从 `officeRibbonTabs.ts` 正则抽取，避免清单与实际功能区脱节；抽取失败**显式失败**（曾经静默当"无参调用"，
  把参数问题伪装成引擎 TypeError）；矩阵少于 40 条即失败（防误删命令）。
- `pnpm --filter @zcode/ui check:office-editor` 还会接着跑 `scripts/check-office-editor-behavior.mjs`：
  用 esbuild 把**我们自己的调度器**（`officeEditorCommands.ts`）打成浏览器模块，在真实引擎上断言真机反馈的五条：
  ① 四种纸张切完页面还在（截图字节数 + 引擎尺寸）；② 六种控件形状互不相同、枚举/复选/单选有选项、日期有格式；
  ③ 复选框控件与日期控件插得进去；④ 分页/连页能来回切；⑤ 缩放设 1.5 能生效、字数统计给数字、查找能定位、
  替换真的改到文档文本（含单字关键词）、公式插成 latex 元素、表格 3×4 就是 3×4、未知命令会明确报错。
- `pnpm --filter @zcode/ui check:office-ribbon-layout`（`scripts/check-office-ribbon-layout.mjs`）：
  esbuild 打真实组件 + tailwind 现场生成 CSS，在 [1600,1280,1040,900,760,660,560,460] 各宽度逐个标签量
  ① 分组行高度是否一致 ② 内容宽度是否超容器（不许横滚）③ 窄宽度下「»」是否可点开且有足够命令
  ④ 下拉互斥（点第二个只剩一个面板）⑤ 面板是否在视口内。

## 4.6 导入前的护栏（数据安全，2026-10-16）

引擎的 docx 插件对一批 Word 特性**直接丢内容**（无头实测，见 `check-office-editor-behavior.mjs`）：

| 特性                                   | 未处理时的后果                           | 我们的处理                                                           |
| -------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------- |
| `w:ins`（修订插入）                    | 插入的**文字直接消失**（整段插入变空段） | 归一化：拆壳保留文字（＝接受插入），并在横幅里说明"修订标记不再写回" |
| `w:del` / `w:moveFrom`                 | —                                        | 归一化：整体删除（＝接受删除）                                       |
| `*PrChange`（格式修订）                | —                                        | 归一化：删掉（保留当前格式）                                         |
| `w:hyperlink`                          | **链接文字消失**                         | 归一化：拆壳保留文字；如实告知"链接地址不会写回"                     |
| `m:oMath`（公式）                      | **公式文字消失**                         | 归一化：用 `m:t` 的文字替换；告知"排版丢失、内容保留"                |
| `w:sdt`（内容控件）                    | 外壳丢失（文字还在）                     | 归一化：拆壳保留内容；告知"变成普通文字"                             |
| `w:commentReference`（批注）           | 锚点与批注**在保存时丢失**               | 归一化：去掉锚点；告知"批注内容不会写回"                             |
| `w:footnoteReference`（脚注）          | 脚注内容**在保存时丢失**                 | **不自动处理**：在横幅里单独列出（这是真会丢内容的项），由用户决定   |
| `w:numPr`（编号）/ `w:fldSimple`（域） | 结构降级（文字保留）                     | 告知"编号变成普通段落 / 域不再自动更新"                              |

护栏行为：`useOfficeDocument.loadDocument` 先跑 `preprocessDocx`（JSZip）→ 有需要告知的特性时
**不导入**，在编辑区上方列出清单，用户点「按上述方式编辑」才用归一化字节打开（另一个出口是「只看只读预览」）。
**体积口径也在这里**：限的是解压后的 `document.xml`（4 MB），不是 docx 文件大小——实测 191 KB 的
docx 解出 2.35 MB document.xml（12 倍），按文件大小限流会放进几十 MB 的文档把面板卡死。

## 4.7 未保存守卫与远端能力探测（2026-10-16）

- **未保存守卫**：脏标记会经 `onDirtyChange` 报给预览面板——退出编辑态（铅笔）前确认；关窗口/刷新由
  `beforeunload` 拦（Electron 弹系统确认框）。**仍拦不住的**：侧栏标签被整体关闭（React 卸载不可取消），
  已记为已知缺口。
- **远端能力探测**：RPC 层没有能力清单，老远端遇到未实现的方法抛 `Method not found`。所以进入编辑前
  用**必然版本不匹配的写入**探一次：新服务端在校验版本时就返回 `File revision mismatch`
  （**发生在任何写盘/备份之前**，见 `fileService.ts` 的实现顺序），老远端抛 `Method not found`，两者可区分且
  不碰文件。探测失败时编辑位只显示说明（不进编辑），避免"编了半天保存不了"。

**已知缺口**（不假装）：

- 改动落成 `w:ins`/`w:del` 的修订模式（C2）未开始；「痕迹」按钮目前映射到引擎的痕迹显示开关；
- 入口未正式化：目前只能从对话里被 Agent 提到的文件卡片进编辑器，文件树/打开方式、独立侧栏标签、远端能力探测都还没有；
- 字体栈只在 macOS 上人工确认过可切换，Windows 字体名的回退顺序未实测；
- **打印对话框**：只验证到"引擎把每页渲成图片、建好打印 iframe 并调用 `print()`"，Electron 里弹不弹对话框要真机看；
- 查找/替换只覆盖**纯文字元素**（表格单元格靠引擎自带的行列坐标，控件/域内文字未验证）。
