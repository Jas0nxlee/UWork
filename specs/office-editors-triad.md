# Word / Excel / PPT 的预览与编辑（三件套规划）

状态：**三种格式的应用内编辑都已落地**（Word 完整编辑器 / Excel 表格编辑 / PPT 文字层保真补丁）。
相关实现 `packages/ui/src/officeEditor/`，门禁 `pnpm --filter @zcode/ui check:office`。
硬约束（用户口径）：**轻量、可随企业包分发、不内置 LibreOffice、覆盖基础功能**。

## 1 选型结论（都经过实测/许可核实）

| 格式      | 预览（只读）                                                          | 编辑（写回真文件）                                                                                                                                                       | 许可与体量                        |
| --------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- |
| **Word**  | `docx-preview`（客户端，已在用）                                      | **canvas-editor**（内核编辑位，已实现：功能区 + 修订 + 批注 + 审阅 + 写回 + 产物校验）                                                                                   | MIT，壳 808 KB + docx 插件 711 KB |
| **Excel** | `@extend-ai/react-xlsx`（已有，**只读**，内部是 WASM 引擎，无写 API） | **`@fortune-sheet/react` v1.0.4（MIT，Luckysheet 官方后继）**：界面 + 公式引擎现成（已落地）；**xlsx 读写是我们写的适配层**（`xlsxWorkbook.ts`：exceljs + **差分写回**） | fortune-sheet MIT、exceljs MIT    |

**Excel 这条为什么不用自己写网格**（2026-10-16 修正上一版计划）：先查有没有像 Word 的 canvas-editor 那样的现成编辑器——
**有**：`@fortune-sheet/react`（MIT）自带公式引擎（fork 自 handsontable/formula-parser）与 Excel 级交互
（多选/边框/填充/合并、行列增删隐藏排序筛选、复制粘贴快捷键、图片/批注/数据验证）。自己搓网格 + 用
formulajs 算公式是多余的路，已作废。**但它不打包 xlsx 读写**（roadmap 里图表/透视未做、条件格式在计划中），
所以：① I/O 由我们写适配层（exceljs ↔ fortune-sheet 工作簿结构）；② 带图表/透视/宏的工作簿仍按护栏走只读。

**被否掉的候选（写清楚，别再走一遍）**：

- **PPTist**（唯一成熟的 OSS 网页 PPT 编辑器，9.4k star）——**AGPL-3.0**，本仓 `scripts/licenses.mjs` 判红，企业分发不能收 ✗；
- **Univer**（Apache-2.0 的表格引擎，PilotDeck 用它做只读预览）——**xlsx 导入/导出在 `@univerjs-pro/exchange`（付费）**，OSS presets 里没有 I/O ✗；只读预览可以用，不值当为它引一整套引擎；
- **HyperFormula**（最完整的公式计算）——**GPL-3.0** ✗；公式交给 fortune-sheet 自带的引擎，不需要它；
- **自建网格 + SheetJS + `@formulajs/formulajs`**——作废：fortune-sheet 已覆盖界面与公式，自建纯属重复劳动；
- **LibreOffice / soffice**——284 MB 侧车 + MPL 旁挂 + 进程管理，与"轻量"冲突 ✗（只保留"本地装了就用"的可选旁挂，不进安装包）；
- **OnlyOffice / Collabora**——服务端重型，早已按用户口径排除 ✗。

## 2 Excel 已落地的实现与**实测边界**

### 2.1 写回是"差分"，不是"重新生成"

保存时重新 `load` 源文件，**只把相对导入快照变了的**格子/合并/列宽行高/冻结/隐藏/表序写回去
（`xlsxWorkbook.writeSheetsToXlsx`）。理由：exceljs 读得懂、但我们没逐个映射的东西
（批注、超链接、数据验证、定义名、打印设置…）会**原样留在工作簿模型里**。
实测（`check-office-excel-io.mjs`，33 条断言）：改一格只写一格（`changedCells=1`），
批注/超链接/数据验证/数字格式/合并/列宽行高/冻结/隐藏表全部逐条保留，部件清单与源文件一致；
改名与**插入工作表**之后各表内容不错位（表按"先名字、再位置"配对——只按位置配对会在插入表时
把每张表的基线错配成邻居的，那是隐藏最深的一类数据事故）。

### 2.2 引擎实测踩到的坑（都进了代码注释与门禁）

| 现象                                                     | 真相                                                                                                                             | 处理                                                                                           |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `allowEdit` 到底管不管用                                 | 文档有、**真的管用**（UI 输入被拦），不用自己拿 `onOp` 拦                                                                        | 只读走 `allowEdit={false}`                                                                     |
| 只读断言"假通过"                                         | 光验"改不动"不够：坐标点歪了也是"改不动"                                                                                         | 门禁里正对照（非只读时同样动作**必须**改得动）                                                 |
| `getSelection()` 取选区                                  | 这套实例里返回 `[{row:[0,null]}]` 这种没设上的占位值 → 所有范围操作静默落到 A1                                                   | **改用 `getSelectionCoordinates()`**（地址串）                                                 |
| 选区越界                                                 | 引擎直接写 `sheet.data[row][col]`，越界即崩（`Cannot set properties of undefined`）→ **白屏**                                    | 所有范围按 `sheet.row/column` **裁剪**；`excelSelectAll` 因此下线                              |
| `mergeCells(range, "mergeAll")`                          | 枚举是**带连字符**的 `merge-all`/`merge-horizontal`/`merge-vertical`（取消是 `merge-cancel`），写错**静默什么都不做**            | 门禁断言"合并后 `config.merge` 有 1 条"                                                        |
| 加粗点第二次变成再加粗                                   | 读回来开着是 `1`、关着是字符串 `"0"`，`=== 1` 判断会误判                                                                         | 判 `=== 1 \|\| === "1"`                                                                        |
| 结构化行列操作                                           | 引擎自己的 `insertRowOrColumn`/`deleteRowOrColumn` 会把表状态弄坏（`sheet.data` 变 0 行，下一次列操作读 `d[0].length` 崩、白屏） | **改走"自己算 + `updateSheet` 整表替换"**（`excelStructure.ts`）：安全，且每一步都能被断言盯住 |
| `updateSheet` 改表级设置                                 | 只在传 `data` 时才替换整表；传 `celldata` 只重建矩阵、**别的字段一律不认**                                                       | 网格线开关仍然不做（做了也是"点了没反应"）                                                     |
| `addSheet` 出来的新表**没有 `data` 矩阵**                | 引擎每次写都是 `sheet.data[row][col] = …`，对着没有矩阵的表下手就崩                                                              | 动手前先补矩阵（`ensureSheetData`）                                                            |
| `getAllSheets()` 给的是 `data` 矩阵、**没有 `celldata`** | 引擎把 celldata 转成矩阵后就把字段删了                                                                                           | 差分读表**两种形状都认**（`cellEntries`）；只认 celldata 会认为"整表被清空"，保存永远失败      |
| 引擎算过公式后 `cell.f` 变成 HTML                        | 它把**显示形态**（带样式 span）写回了 `f`                                                                                        | 读引擎数据时统一还原成文本（`formulaText`），否则会把 HTML 当公式写进文件                      |
| `spliceRows/spliceColumns` 只搬值/样式/行高              | **批注与数据验证不跟着走**                                                                                                       | 自己搬（`moveDecorations`）；批注只能用内部字段清（`note = null` 会让写出直接抛）              |
| 公式引用不会随搬移改写                                   | `spliceRows` 搬的是文本                                                                                                          | 搬完再按同一操作改写文件里的公式（`rewriteWorksheetFormulas`）                                 |
| `unMergeCells` 会清空从属格                              | 先写格子再取消合并 → 刚写的公式被抹掉                                                                                            | 写回顺序固定为**先合并/取消合并、再写格子**                                                    |

### 2.2b 已修：编辑位里"点单元格选不中／跳回 A1"

**症状**（用户真机反馈）：网格画得出来、文件也读进来了，但**点任何单元格都选不中**——选区闪一下、
名字框一直 `A1:NaN`，点下去还会跳回 A1。

**根因：引擎的宿主形状。** fortune-sheet 的 `Workbook` 在**自己的 React root** 里挂时，
"行列 ↔ 像素"的命中表算得对；**嵌在编辑位的组件树里**（外面还有工具栏/功能区/我们自己的状态更新），
它这张表会算成 NaN：命中判定用 `y + ctx.scrollTop` 反算行列，NaN 一路传下去 →
选中一个"不存在的格子"、地址算不出来（`A1:NaN`）、`cellFocus` 把视图滚到左上角（跳回 A1）。

**修法**：编辑位改成 `EngineHost`——引擎挂在**它自己的 root** 里（`createRoot(引擎宿主).render(<Workbook/>)`），
编辑位只管自己的状态（功能区、状态栏、脏标记），引擎实例通过 `apiRef` 交回来；换文件/重新加载时
卸载旧 root 并清空宿主（引擎的 canvas 不会被 React 自己摘掉，留着会画出两份）。

**排查中确认/排除的**（记下来，省得再走一遍）：

- 点击**确实到达**引擎、引擎**确实设置了选区**：把滚动状态手动归零一次，名字框立刻显示出被点的格子
  （所以问题在"算地址"这一步，不在事件）；`api.scroll({0,0})` 能临时修好、下次渲染又坏 → 就是"量错"而不是"没点着"。
- 排除：React dev/prod 模式、`hooks`、`key`、`data` 引用变化、重复载入（只读一次文件）、渲染风暴
  （实例与渲染次数稳定）、事件被上层吞掉、容器尺寸守卫（按其公式复算没越界）、冻结窗格、嵌套/flex 布局、
  缺 Tailwind 样式、挂载时机（延迟挂载没用）。
- **顺带修掉一个真问题**：`onOp` 是引擎在**渲染期**（reducer 里）回调的，里面同步 `setDirty` 会让 React
  报"边渲染边更新另一个组件"（控制台有警告）。改成 `queueMicrotask` 后警告消失。它不是本 bug 的根因，但确实是错的。
- **门禁缺口**：四套检查全绿也漏了这个 bug，因为它们只驱动**裸引擎**。现在
  `check-office-excel-ui.mjs` 加了"编辑位形状"的两条断言（点单元格必须选中、能直接打字改值），
  而且断言前会**等值稳定**（引擎提交状态是异步的，单次读取会偶发读到上一拍，曾让加粗的切换断言偶发失败）。

### 2.2c 全按键点测（`check-office-excel-buttons.mjs`）与查出的问题

用户要求"所有功能和按键都测一遍"，所以加了一条**真 DOM 点测**：把功能区每个按钮、每个下拉的
**每一个选项**都在真编辑位里点一遍（95 个控件，每个都在新挂载的实例上跑），判定口径是
①不报错 ②引擎还活着 ③**表状态/选区/状态栏至少变了一样**（少数正当的 noop 单独标出来，
例如空历史时的撤销/重做、以及"选的就是当前值"的字号）。另外对 10 项关键功能做具体断言
（加粗切换、数字格式落格、合并/取消合并、行列搬家、整表选中、保存写回、重载等）。

这条检查当场查出并修掉了两个真问题：

1. **「新建一张工作表」把编辑区弄崩**：切表/新建表的**瞬间**引擎那张表还没有 `data` 矩阵，
   而编辑位的选区刷新会去读格子 → 抛 `sheet not found` → 整个编辑区白屏、后面所有按钮跟着失效。
   修法：选区刷新里的读格子全部兜住异常（中间态跳过这一拍）。
2. **卸载引擎宿主时 React 报错**：`EngineHost` 在自己的 cleanup 里同步销毁另一个 root，
   React 会报 "Attempted to synchronously unmount a root while React was already rendering"，
   而且 DOM 拆不干净（`removeChild` 报错、残留一份画布）——用户关掉编辑器/切文件时就会碰到。
   修法：把销毁推到本轮渲染之后（`setTimeout(…, 0)`）。

**已知问题（记在这，别当它不存在）**：引擎自己的**工作表标签点了不切换**（`luckysheet-sheets-item`）。
对照实验：裸引擎同样不切换，与"只给 celldata / 先转成 data 矩阵"无关。
点击确实落在标签上（命中测试通过）、也没有报错，就是不换表。
临时办法：用我们功能区的「新建工作表」建表没问题；**切表**目前只能靠对话/Agent 或外部编辑器。
点测里把它标成"已知问题"（照实打印，不让门禁变红），根因待查。

### 2.3 Excel 现在能做什么 / 不做什么

**能**：单元格改值、公式（引擎自算，含 `=SUM` 自动求和）、字体/字号/加粗斜体下划线删除线/字色/填充、
水平对齐/自动换行、合并居中/取消合并、数字格式（常规/数字/整数/千分位/百分比/货币/日期/文本）、
清除内容/清除格式、撤销重做、**插入/删除行列**、整表选中、冻结首行/首列/行列/取消、新建工作表、
另存写回（版本比对 + sibling 备份 + 产物校验）。

**插入/删除行列是"自己算"的**（引擎那条路会崩，见上表）：变换会连着处理
**值、合并区域、行高列宽、隐藏行列、冻结位置、公式里的 A1 引用**；写回时用 exceljs 的整行/整列搬移，
所以**批注与数据验证也跟着走**。公式引用按 Excel 的语义改（`=SUM(A1:A2)` 中间插一行 → `=SUM(A1:A3)`，
删掉被引用的行 → `#REF!`）；跨表引用（`'表'!A1`）不动——猜错比不改更糟。

**不做**（如实写清）：网格线开关（引擎不认表级字段）、图表/透视/宏/切片器/外部连接/条件格式/图片/
结构化表格（**护栏命中即只读**）、批注与数据验证的**编辑**（能原样保留并跟着行列搬，不能新增/修改）。

## 2 三种格式能"完善"到什么程度（如实写清）

- **Word：完整编辑器**（已达成）。文字/段落/字体/颜色/对齐/列表/行距/表格/图片/链接/公式/分页/分栏/水印/纸张与页边距/缩放/查找替换/字数/修订显示与逐条接受拒绝/批注气泡与审阅窗格/写回（备份+冲突拒绝+修订与批注保真+页眉页脚回填+产物校验）。
  **不做**：脚注内容（会丢，导入前拦一次）、批注回复/解决、页眉页脚编辑、目录/域更新、拼写检查。
- **Excel：可编辑表格**（**已达成**，见 §2.3 的能/不能清单）。
- **PPT：只读预览 + 文字级编辑**（**已达成**，见 §3-PPT）。没有可用的 OSS pptx 编辑器，所以做"**保真补丁**"：幻灯片列表（缩略图）+ 选中页里逐个文本框编辑（textarea）→ 只改 `ppt/slides/slideN.xml` 的文本节点，其余部件**逐字节保留**（图片、母版、动画、备注都不动）。这让"改字"这件事可用且安全，但**不是** WYSIWYG 排版编辑器。
  **不做**：拖拽排版、添加形状/图片/动画、母版编辑（这些需要自研渲染+编辑器，不在"轻量"预算内）。

## 3 PPT 已落地的实现（文字层保真补丁）

没有可用的 OSS pptx 编辑器（见 §1），所以做的是**"改字"而且不碰别的**：

- **模型**：按 `a:txBody` 编号（文档序）。注意 `txBody` 有**两个命名空间**——形状里是 `p:txBody`、
  表格单元格里是 `a:txBody`，只认一个就会漏掉另一类（实测：正文框全丢、只剩表格）。
- **读**：段落＝行；同一段里被 PowerPoint 拆开的多个 `a:t`（甚至一个 run 里多个 `a:t`）**拼接成一行**；
  段内换行 `a:br` 拆成两行、段尾的 `a:br` 忽略；`a:fld`（页码等域）不参与编辑也不被破坏。
- **写**：只在**源 zip 上替换被改过的那几张 `ppt/slides/slideN.xml`**，其余部件逐字节保留
  （图片、母版、版式、动画、备注一个字节不动）。改一行时首个 run 承载全文、其余 run 清空（样式留着）；
  段落数变化时新增行**克隆首段**（沿用它的 `pPr` 与首个 run 的 `rPr`），不是变成默认字体。
- **校验**（`pptxValidate.ts`）：zip 可读 + 必要部件在 + 幻灯片数不变 +
  **未被编辑的部件内容逐字节一致**（这条是"保真"的硬证据）+ 每页 XML 可解析 + 文字量没塌两成。
  不过就不写盘。
- **回归**（`check-office-pptx.mjs`，18 条）：解析正确（拆开的 run / 段内换行 / 表格）→ 改一行只动一页
  → 其余部件哈希不变 → 新增行沿用样式 → **产物能被产品在用的 pptx 渲染器打开**（`@aiden0z/pptx-renderer`
  的 `parseZip` + `buildPresentation`）→ 三种坏产物（偷改图片 / 清空文字 / 丢幻灯片）都被校验拦住。

**不做**（如实写在界面上）：拖拽排版、添加形状/图片/动画、母版与版式编辑、文本框位置大小、
同一段里的多字体（改动那一行会折叠成首个字体）、备注编辑（按需再加）。

7. **Excel 补强**（视用户反馈）：结构化行列操作（需要绕开引擎的坏路径：自己算 celldata + `updateSheet`
   只带 `celldata` 回灌，公式引用要跟着改）、批注/数据验证编辑、图表感知的保真补丁写回。

## 3b PPT 现在是编辑器，不只是"改字"（2026-10-18 扩写）

上一版 PPT 只做文字补丁，用户反馈"PPT 不能只有文字编辑"，于是按同一条**保真补丁**路线把能力扩到：

**形状层**（`pptShapes.ts` / `pptShapeFormat.ts` / `pptShapeInsert.ts`）：

- 列出每页的形状（名字、类型、几何、段落格式）；
- 改**位置与大小**（X/Y/宽/高，界面上用厘米，XML 里是 EMU；缺省继承版式的形状会补一个显式 `a:xfrm`）；
- 改**文字格式**：粗/斜/下划线/删除线、字号、颜色、字体；**段落**：左/中/右/两端 + 项目符号开关；
- **层级**（上移/下移一层 = 调整 `p:spTree` 里 children 的顺序）、**复制形状**（新 id/名字"副本"/位置偏移）、
  **删除形状**、**新建文本框**（自己造 `p:sp` 三件套 + 唯一 id）。

**幻灯片层**（`pptSlides.ts`）：新建（空白页）、复制、删除、**调整放映顺序**。
顺序的来源是 `p:sldIdLst`（**不是** slideN.xml 的文件名——PowerPoint 完全可以让第 1 页叫 slide7.xml）；
增删会同时维护 `ppt/_rels/presentation.xml.rels` 与 `[Content_Types].xml`。

**界面**（`PptxEditorPane.tsx` + `PptxShapeInspector.tsx`）：左边幻灯片列表 + 增删排序按钮，
右边形状列表（点一个选中）+ 每块文字的多行输入，底部是选中形状的检查器（几何/格式/段落/层级/复制/删除）。

**保真底线照旧**：改动只落在被编辑的那几页 XML 上；图片、母版、版式、动画、备注、主题**逐字节保留**
（回归里有一条"只动了该动的部件"专门盯着它），产物仍要能被产品在用的渲染器打开。

**还没做**：动画与母版编辑、插入图片/图表、表格编辑、备注编辑、同一段里的多字体。

## 3c 画布级编辑：在幻灯片上直接点选 / 拖动 / 拉角缩放（2026-10-18）

`PptxSlideCanvas.tsx`：用**产品在用的同一个渲染器**（`pptxRendererPreviewEngine`）把当前页画出来，
上面叠一层交互层——点形状选中、拖动移动、拉四角缩放、双击把焦点交给对应文本框（就地改字）。
渲染器已经能给出每个形状的 `p:cNvPr@name` 与几何，所以这一步是**接线**，不是重写引擎。

- **两套坐标，别混**：XML 里（`a:off`/`a:ext`）是 **EMU**（1 厘米 = 360000）；渲染器给的是
  **96 dpi 像素**（`pageSize` 就是 960×720，因为一页 9144000 EMU = 10 英寸），
  **1 px = 9525 EMU**（914400 ÷ 96）。组件内部**一律按 EMU 记账**（读渲染器的几何立刻 ×9525），
  只在画到屏幕上时才 `px = emu ÷ 9525 × scale`（`scale = 图层宽 ÷ pageSize.width`），写回时反着来。
- **点选名单以本页 XML 为准**：渲染器还会画**从版式/母版继承来的**形状，它们不在本页 XML 里、
  改了也写不回去，所以不进点选名单——宁可点不到，不能"拖了半天没反应"。
  几何优先用显式 `a:xfrm`；没有（继承版式）就用渲染器量到的框；两个都没有就不给拖，
  提示去检查器里填一次（一提交就落下显式几何，之后画布上就能拖）。
- **拖动只写一次**：实时几何只在显示层（`draft`），松手才写回 XML → 一次拖动 = 一条改动；
  只是点了一下（位移 < 0.03 厘米）不写回、也不制造"改动"。
- **喂给渲染器的是编辑后的字节**：渲染器接整份文件，而改动只在 XML 映射里，所以每改一次就重算一份
  `previewBytes`（`pptDeckCompose.ts`，只替换改过的那几页，与保存共用"当前状态"口径）——
  画布因此显示的是**当前状态**，不是打开时那一版。
- **双击就地改字**：形状的 `txBody` 与 `readSlideText` 的文本块是**两套编号**，不靠顺序猜，
  按文字内容（去空白）匹配到对应 textarea 并给它焦点；匹配不上就退到这一页第一个文本框，
  并在状态栏说明白。

**踩到的坑（都是门禁/真机逼出来的）**：

- **渲染器的几何不是 EMU，是 96 dpi 像素**：按 EMU 算会把位移放大 9525 倍
  （一次 60px 的拖动就把形状挪出页面）。回归里把 `9525` **另写一遍**——两边一起错才会"通过"。
- **检查脚手架页面里没有 Tailwind**：画布原先用 class 写 `relative` / `overflow-hidden` /
  `origin-top-left`，在那儿全部失效——缩放层绕中心放大、盖住整个编辑位，左侧幻灯片列表点不动
  （Playwright 报 `subtree intercepts pointer events`）。**几何相关的 CSS 一律写 inline style**
  （颜色/边框等样式继续用 class），这样有无 Tailwind 都成立。

**回归**（`lib/officePptxCanvasCases.mjs`，8 条，真鼠标事件）：渲染出页 → 点中形状就选中（4 个手柄）
→ 拖 60px 后 `a:off` 精确增加 463378 EMU（= 60 ÷ scale × 9525，实测与期望**完全一致**）
→ 拖动不改大小 → 改动后画布重画（渲染的 DOM 换了一棵新的，证明喂进去的是编辑后的字节）
→ 拉右下角 `a:ext` 变大而左上角不动 → 点空白取消选择 → 双击把焦点交给对应文本框。

### 3b.1 形状层踩到的坑（都进了注释与回归）

- **`txBody` 有两个命名空间**（形状 `p:txBody`、表格单元格 `a:txBody`）：只认一个的话"改文字格式点了没反应"；
  新建时也要用对前缀（`p:sp` 里塞 `a:txBody` 是无效 XML）。
- **`a:rPr` 里的子元素有顺序**：`a:solidFill` 要排在 `a:latin` 前面，否则 PowerPoint 会认为文件损坏。
- **JSZip 会消费传入的 ArrayBuffer**（同一份 buffer 第二次 `loadAsync` 就报"读不到数据"）：
  所有 JSZip 入口一律**先切片**（`bytes.slice(0)`），调用方不用操心 buffer 生命周期——
  这条在 PPT 的幻灯片操作里踩得最狠（一次"新建/复制/移动/删除"连着做就会中招）。
- 形状/幻灯片改动**不经过 React state**（XML 在 ref 里），界面要靠一个 `revision` 版本号重算，
  否则"新建文本框点了没出现"（列表是旧的）。

## 3d PPT 面板改为 PowerPoint 的形态（2026-10-18，用户口径："你这根本就不是 PowerPoint 的那个面板形式"）

上一版 PPT 编辑位的**能力**在（形状增删改、幻灯片增删排序、画布点选拖动缩放都对，回归也全绿），
但**形式**不像 PowerPoint：左边是一列文字（不是缩略图）、属性塞在底部一条检查器、正文靠一堆 textarea 编辑。
用户的要求是**去看开源的实现与我们自己技术栈的 demo**，照那个形式做。查证结论（都是实测/官方资料，别再重查）：

1. **我们在用的渲染器自带这种面板**：`@aiden0z/pptx-renderer`（Apache-2.0）的官方 demo
   （`aiden0z.github.io/pptx-renderer`）版式就是 PowerPoint 式：左侧 SEARCH + 上一页/下一页 +
   **真实缩略图列表**（当前页高亮框）、右侧大画布、右下页码。它的 API 里有编辑需要的全部扩展点：
   `renderThumbnailToContainer`（缩略图）、`renderSlide`/`goToSlide`、`setZoom`/`setFitMode`、
   `searchText` + `highlightSearchResult`（节点级、随页面一起缩放的覆盖层）、
   `afterSingleSlideRender()`（注释写明"子类可以挂额外 UI，例如导航按钮"）。
   → 面板形式照它做：**左上缩略图 / 中画布 + 右下缩放 / 右侧任务窗格 / 顶部功能区**。
2. **PPTist（唯一的成熟开源网页 PPT 编辑器，9.4k stars，AGPL-3.0 ✗ 不能收）怎么做的**：
   左缩略图面板 + 顶工具栏 + **右属性面板**；画布交互用 **`moveable`（MIT）** + `selecto`（MIT）
   ——8 个手柄 + 旋转 + 等比缩放；形状内文字编辑用 ProseMirror。
   → 许可上 PPTist 本身不能用，但**它用的交互库是 MIT、可以直接用**，手柄不再手搓。
3. **Univer 的 Slides 现在是 OSS**（`@univerjs/slides` / `@univerjs/slides-ui` 1.1.0，Apache-2.0）。
   但**pptx 导入导出不在 OSS 包里**（依赖只有 core + engine-render），等于 I/O 仍要我们写；
   而"整份 pptx → 别人的模型 → 再转回来"会丢掉我们现在**字节级保真**（只替换改过的页）这条底线。
   → **看过，不采用**（与 Univer Sheets 被否是同一个理由：I/O 不在 OSS，且会牺牲保真）。

### 落地面（按此顺序做，每一步都在真机（dev 应用 + CDP）里看过再往下）

**已落地（2026-10-19，真机截图逐项看过）**：

1. **左栏＝真缩略图面板**：`usePptxPreview` 一份文件只解析一次（之前画布每次改动都重开一份、缩略图再各开一份），
   画布与缩略图共用；每页用渲染器画真缩略图（进入视口才画）、页码、当前页高亮、增删排序按钮。
2. **中栏＝画布 + 右下缩放**：页面用 `margin:auto` 居中；**Ctrl/⌘ + 滚轮以指针为中心缩放**（非 passive 监听，
   拦掉浏览器缩放），缩放后把指针下的那点滚回原位；右下角 − 100% ＋ 适应 档位。
3. **右栏＝「设置形状格式」任务窗格**：形状几何/文字格式/段落/层级/复制删除 + 形状列表 + 文本块。
   **默认收起**（用户口径：一直占 288px 会把画布挤窄），选中形状自动弹出，点 ✕ 收起；
   画布右下有「设置形状格式」入口。
4. **顶栏＝功能区**（`pptxRibbonTabs.ts` + `pptxRibbonRun.ts`，复用 Word/Excel 的功能区外壳）：
   开始（幻灯片 / 字体 / 段落 / 形状）、插入（文本 / 幻灯片）、视图（缩放）。
   **只放真能执行的命令**——切换/动画/放映/审阅一个都不摆；命令名与 Word/Excel 同名
   （`executeBold` / `executeRowFlex` / `executeFont`…），于是"加粗亮不亮、对齐亮不亮"直接用现成判定，
   选中态的取值来自新加的 `PptxShape.runFormat`（读首个 run 的 `a:rPr`）。

**这一步在真机里逼出来的两个 bug**（都进了回归）：

- **画布框被页面撑宽的正反馈**：页面宽是按"框宽"算的，而 flex 子项默认 `min-width:auto` →
  `页面变大 → 列变宽 → 页面更大`。真机实测滚轮放大一次，页面从 816px 涨到 **27794px**。
  修法：中间列 `min-width:0` + 画布框 `width/max-width:100%`；回归里断言"缩放前后框宽不变"。
- **共享预览文档被同步销毁**：改动后 `bytes` 变 → 旧文档 `dispose()`，而画布/缩略图可能还有一次读在飞 →
  撞 `Presentation preview document has been disposed`，整个编辑位变成错误页（真机实测，编辑一次必现）。
  修法：销毁推迟一轮（`setTimeout 0`）+ 读几何 `try/catch`——与 Excel 引擎宿主卸载是同一个坑。

**面板行为回归**（`lib/officePptxPanelCases.mjs`，5 条）：窗格默认收起 → 画布占满；在画布上点形状 →
窗格自动弹出、点 ✕ 收起；页面居中（左右留白差 ≤2px）；Ctrl+滚轮以指针为中心缩放且**不把框撑宽**；
功能区回归（`lib/officePptxRibbonCases.mjs`，5 条）：标签存在、没选中形状时命令要说人话、
选中后加粗落到 XML、视图缩放改画布、新建幻灯片页数 +1。

**2026-10-19 第二条反馈（四条，全部落地）**：

- **折叠菜单滚不动也点不着**：`»` 面板关闭监听写成了 `document.addEventListener("scroll", onClose, true)`
  ——捕获一切滚动，**在面板里滚动被当成"该关闭"**。现在面板自己的滚动不算，面板高度按视口夹取、内部滚动。
- **按键描述占太宽**：PPT 功能区用的 4 个图标名（`SlideAdd24Regular`/`Copy24Regular`/`Textbox24Regular`/
  `TextBulletList24Regular`）**不在图标表里** → 取不到图标就退回显示整条文字。补进表后按钮只显图标
  （加粗 0 文字、32px 宽），开始标签 13 个按钮里只有字体/字号/颜色三个下拉带文字。
  **教训**：加图标名要对着安装包的 `lib/*.d.ts` 核一遍（`TextAdd24Regular` 就不存在，实际叫 `Textbox24Regular`）。
- **面板弹出时不该盖住页面**：改成**适应窗口**（缩放按可用宽/高取小者）+ 面板**占布局**（不浮层）。
  真机实测：两面板都收起 640px/0.648 → 开缩略图 488px/0.49 → 再开窗格 200px/0.19，每一步整页都完整可见。
- **页面上下也要居中**：页面盒子 `margin:auto` + 画布框吃满剩余高度（去掉固定 620 上限），实测上下 218/218、左右 9/9。

**就地改字（双击形状，在页面上改）**：编辑层盖在形状位置上，字号/对齐/颜色/粗细按该形状的 `a:rPr` 算
（40 磅 → 33.7px @ scale 0.63）；⌘/Ctrl+↵ 或点别处提交（走同一条文本补丁，保存仍只写回改过的那页），Esc 放弃。
**坑**：双击的**第二下**会把刚聚焦的编辑层 blur 掉，看起来就是"双击没反应"——300ms 内的失焦要重新聚焦、
不当作提交（真机踩到、回归里钉住）。

**检查脚手架的教训（重要）**：裸检查页**没有 Tailwind**，flex/宽度类全部失效 →
"面板占布局、画布让位"这类**布局断言必须放在带 Tailwind 的那一遍**（`officePptxStyledCanvasCases`），
裸页面里只验"几何/交互/整页可见"。

**2026-10-19 第三条反馈（三条，全部落地）**：

- **按选中对象显示设置**：右栏不再拿形状的文字格式套在图片上——`sp` 给文字/段落，`pic` 给位置/大小/层级/
  复制删除 + 一句"裁剪/亮度/替换还没做"，表格说明"只能改单元格文字（在「文本」里）"。
- **"删掉图形画布不更新"的真根因是差分写回**：`applyDeckPatch`（插图片/加页走的通道）只给**新增**部件设基线，
  改动过的页没设 → `source` 已经是"带图"的、`baseline` 还是"原始无图"的；删除时 XML 正好回到基线内容 →
  差分判"没变"→ **跳过写回，zip 里留住了补丁版本**。修法：补丁改过的页也**基线前移**（`previous.parts` 比一遍），
  `(source, baseline)` 从此一致。**教训**：差分写回的前提是"基线 == source 的内容"，两处必须一起前移。
- **插图片**：功能区「插入 → 图片」→ 取值对话框选本机文件 → 新增 `ppt/media/imageN.*`、补这一页 `.rels`、
  在 `spTree` 末尾插 `p:pic`，按宽高比等比放进页面中央（最多占页面宽 60%）；走 deck 补丁，其余部件逐字节保留。
- **顺带修掉一个真 bug**：收进「»」面板的"需要取值"命令（图片/超链接这类）**点不动**——面板一点就关、
  按钮随之卸载，**取值对话框跟着组件一起消失**。现在对话框挂在功能区根部（`RibbonPromptDialog` + 上下文
  里的 `promptItem`），只有"展开状态"能用的功能从今天起在折叠状态也能用。

**排查脚手架（可复用）**：`__pptxPane` 上挂了预览重算次数、最后一次错误、**当前喂给渲染器的字节**、
模型里某页的 XML——"改了画布没动"这类问题靠这几样一眼定位（这次就是靠它把范围从"渲染"缩到"写回"）。

## 4 与 PilotDeck 的对照（为什么不做成它们那样）

PilotDeck（OpenBMB）三种格式**全是只读预览**，编辑交给 agent 技能脚本改真文件（`skills/docx|pptx|spreadsheets`），
高保真预览靠服务端 `soffice --headless --convert-to pdf`。我们**预览侧与它同源**（同一批库），
差别在编辑：它没有应用内编辑，我们在 Word 上已有完整编辑器，Excel/PPT 按上表补齐——
这条路更重，但用户要的是"应用内像 Office 一样编辑"，不是"让 agent 改文件"。
