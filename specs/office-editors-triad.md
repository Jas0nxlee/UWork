# Word / Excel / PPT 的预览与编辑（三件套规划）

状态：规划 + Excel 第一步（护栏）落地。相关实现 `packages/ui/src/officeEditor/`。
硬约束（用户口径）：**轻量、可随企业包分发、不内置 LibreOffice、覆盖基础功能**。

## 1 选型结论（都经过实测/许可核实）

| 格式      | 预览（只读）                                                          | 编辑（写回真文件）                                                                                                                                                                                       | 许可与体量                        |
| --------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| **Word**  | `docx-preview`（客户端，已在用）                                      | **canvas-editor**（内核编辑位，已实现：功能区 + 修订 + 批注 + 审阅 + 写回 + 产物校验）                                                                                                                   | MIT，壳 808 KB + docx 插件 711 KB |
| **Excel** | `@extend-ai/react-xlsx`（已有，**只读**，内部是 WASM 引擎，无写 API） | **`@fortune-sheet/react` v1.0.4（MIT，Luckysheet 官方后继）**：界面 + 公式引擎现成；**xlsx 读写要我们写一层适配**（官方 I/O 是独立插件 `corbe30/fortuneexcel`，基于 `exceljs`；`luckyexcel` 是同类参考） | fortune-sheet MIT、exceljs MIT    |
| **PPT**   | `@aiden0z/pptx-renderer`（已在用，只读）                              | **无 OSS 可用的 pptx 编辑器**（见下）→ 走"保真补丁"路线：只改 `ppt/slides/slideN.xml` 里的文字，其余部件逐字节保留                                                                                       | 渲染器已在依赖里                  |

**Excel 这条为什么不用自己写网格**（2026-10-16 修正上一版计划）：先查有没有像 Word 的 canvas-editor 那样的现成编辑器——
**有**：`@fortune-sheet/react`（MIT）自带公式引擎（fork 自 handsontable/formula-parser）与 Excel 级交互
（多选/边框/填充/合并、行列增删隐藏排序筛选、复制粘贴快捷键、图片/批注/数据验证）。自己搓网格 + 用
formulajs 算公式是多余的路，已作废。**但它不打包 xlsx 读写**（roadmap 里图表/透视未做、条件格式在计划中），
所以：① I/O 由我们写适配层（exceljs ↔ fortune-sheet 工作簿结构）；② 带图表/透视/宏的工作簿仍按护栏走只读。

**被否掉的候选（写清楚，别再走一遍）**：

- **PPTist**（唯一成熟的 OSS 网页 PPT 编辑器，9.4k star）——**AGPL-3.0**，本仓 `scripts/licenses.mjs` 判红，企业分发不能收 ✗；
- **Univer**（Apache-2.0 的表格引擎，PilotDeck 用它做只读预览）——**xlsx 导入/导出在 `@univerjs-pro/exchange`（付费）**，OSS presets 里没有 I/O ✗；只读预览可以用，不值当为它引一整套引擎；
- **HyperFormula**（最完整的公式计算）——**GPL-3.0** ✗；公式交给 fortune-sheet 自带的引擎，不需要它；
- **自建网格 + SheetJS + `@formulajs/formulajs`**——作废：fortune-sheet 已覆盖界面与公式，自建纯属重复劳动；
- **LibreOffice / soffice**——284 MB 侧车 + MPL 旁挂 + 进程管理，与"轻量"冲突 ✗（只保留"本地装了就用"的可选旁挂，不进安装包）；
- **OnlyOffice / Collabora**——服务端重型，早已按用户口径排除 ✗。

## 2 三种格式能"完善"到什么程度（如实写清）

- **Word：完整编辑器**（已达成）。文字/段落/字体/颜色/对齐/列表/行距/表格/图片/链接/公式/分页/分栏/水印/纸张与页边距/缩放/查找替换/字数/修订显示与逐条接受拒绝/批注气泡与审阅窗格/写回（备份+冲突拒绝+修订与批注保真+页眉页脚回填+产物校验）。
  **不做**：脚注内容（会丢，导入前拦一次）、批注回复/解决、页眉页脚编辑、目录/域更新、拼写检查。
- **Excel：可编辑表格**（目标，引擎用 fortune-sheet）。单元格改值、公式（引擎自算）、字体/字号/加粗/颜色/对齐、行高列宽、合并单元格、多工作表、插入删除行列、保存写回（exceljs 适配 + 产物校验）。
  **保真策略**：适配层重写 xlsx 会丢图表/透视表/宏/图片等（fortune-sheet 本身不做这些）——所以**导入前先护栏**
  （`xlsxPreflight.ts`）：命中这些特性就**不允许编辑**（只读预览 + 说明），而不是"改完把图表弄没了"。
  后续可做"只补丁改动的工作表"（`xl/worksheets/sheetN.xml` + `sharedStrings.xml`），把保真度提到与 Word 同级。
- **PPT：只读预览 + 文字级编辑**（现实上限）。没有可用的 OSS pptx 编辑器，所以做"**保真补丁**"：幻灯片列表（缩略图）+ 选中页里逐个文本框编辑（textarea）→ 只改 `ppt/slides/slideN.xml` 的文本节点，其余部件**逐字节保留**（图片、母版、动画、备注都不动）。这让"改字"这件事可用且安全，但**不是** WYSIWYG 排版编辑器。
  **不做**：拖拽排版、添加形状/图片/动画、母版编辑（这些需要自研渲染+编辑器，不在"轻量"预算内）。

## 3 分期（按此顺序做）

1. **Excel 护栏**（已写）：识别"重写会丢"的特性（图表/透视/宏/图片/结构化表格/切片器/批注/条件格式/数据验证），
   命中就只读（与 Word 同款的导入前横幅）。
2. **Excel 编辑位（fortune-sheet 接入）**：装 `@fortune-sheet/react`，先在独立页验证：React 19 兼容性、
   包体量、只读模式的可行做法（它没文档化 readOnly，需要靠 `onOp` 拦截 + 样式处理）、以及 I/O 适配难度
   （exceljs ↔ fortune-sheet 工作簿结构，参考 luckyexcel）。
3. **Excel 适配层 + 写回**：xlsx→工作簿、工作簿→xlsx（exceljs），保存走 `writeBinaryFile`（复用 Word 的
   版本比对/备份/原子替换）+ 产物校验（zip/XML/关系 + 内容塌陷 + 工作表数不变）。
4. **Excel 功能区**：复用 Word 的功能区外壳（三级自适应 + 分组取舍），接单元格格式/行列/表格工具。
5. **PPT 文字级编辑**：幻灯片列表 + 文本框架编辑 + 保真补丁写回 + 产物校验。
6. **PPT 增强**（视需要）：备注编辑、文本框增删、按渲染器命中做"点哪儿改哪儿"。

## 4 与 PilotDeck 的对照（为什么不做成它们那样）

PilotDeck（OpenBMB）三种格式**全是只读预览**，编辑交给 agent 技能脚本改真文件（`skills/docx|pptx|spreadsheets`），
高保真预览靠服务端 `soffice --headless --convert-to pdf`。我们**预览侧与它同源**（同一批库），
差别在编辑：它没有应用内编辑，我们在 Word 上已有完整编辑器，Excel/PPT 按上表补齐——
这条路更重，但用户要的是"应用内像 Office 一样编辑"，不是"让 agent 改文件"。
