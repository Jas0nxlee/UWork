## 新增与改进

- 支持企业网关接入：企业微信登录后同步 UCAS 网关地址、企业密钥及可用模型；已有手工配置的密钥不会被自动覆盖。
- 设置页提供企业套餐、用量趋势和模型同步入口。套餐与用量仅供查看，不提供购买、重置或撤销密钥操作。
- UWork 使用独立的用户数据与 Electron profile 目录，减少与上游 ZCode 的配置和会话相互影响。
- 统一 UWork 图标、目录规则与打包测试；五个平台继续预置经过校验的企业微信公开登录配置，并验证全新数据目录中的扫码入口。

- 修复干净环境中浏览器/电脑控制共享主机的类型依赖，恢复跨平台打包；发布检查新增完整桌面 Agent 构建。

## 安全修复

- 升级已发布修复版本的依赖，移除界面未使用的 shadcn CLI 依赖链，保留原有组件样式。
- 自签 CA 改用 Node 原生加密实现；已有证书和私钥按原路径复用。
- MCP OAuth 刷新在发送 refresh token 或 client secret 前校验保存的授权服务器身份，拒绝把旧凭据发送到变更后的 issuer。
- 调试工具使用固定源码提交的 forge 安全补丁，并通过真实 RSA 验签回归。对应上游 PR 尚未合并、尚未发布正式 npm 修复版：https://github.com/digitalbazaar/forge/pull/1152 。

## 升级注意事项

- 用户级数据现在保存在 `~/.uwork`，不自动迁移、读取或删除原来的 `~/.zcode` 数据。首次升级可能需要重新登录、选择工作区并重新配置个人供应商；旧目录仍保留。
- 工作区内的 `.zcode/AGENTS.md` 等项目约定保持兼容。
- 历史 MCP OAuth 凭据缺少 issuer 时，需要重新完成授权；原凭据不会因刷新被静默覆盖或删除。
- 随包第三方许可声明已更新；部分历史版本的原始版权/许可材料仍需上游复核，清单保留相应标记。

## 验证范围

- 正式发布需通过类型、Lint、架构、行为与安全回归、生产依赖审计，以及 macOS arm64/x64、Windows x64、Linux x64/arm64 构建和全新数据扫码入口测试。
- 新设备扫码入口测试验证配置可用、原生扫码视图可打开；不代表已完成真实企业账号认证、模型对话或所有平台的人工验收。
